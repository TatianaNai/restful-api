# Todo API tests

Реализован фреймворк для проверки API приложения TODO manager. Написаны автоматизированные тесты, проверяющие CRUD-операции (GET в т.ч. с параметрами limit и offset, POST, DELETE, PUT).  
Тесты написаны с помощью фреймворков Retrofit, JUnit 5.

Реализованные тесты:  
• GET /todos  
Проверка получения списка задач  
Проверка параметров offset и limit  
• POST /todos  
Создание новой задачи  
Негативные проверки (отсутствие обязательных параметров)  
• PUT /todos/{id}  
Обновление существующей задачи  
Негативные проверки (обновление не существующей задачи)  
• DELETE /todos/{id}  
Удаление существующей задачи  
Негативные проверки (удаление не существующей задачи)  

Проведены тесты производительности POST запроса с помощью Apache JMeter. Тесты запускались локально через JMeter (GUI). Также предусмотрена возможность запуска тестов через Maven на фазе verify (подключен jmeter-maven-plugin), в начале прогоняются обычные тесты и после Performance тесты. Файл Test Post.jmx можно открыть при помощи локального JMeter и посмотреть результаты стресс тестов.    

В виду отсутствия информации об ожидаемой нагрузки и цели, тесты запускались с параметрами:  

| Number of Threads | Ramp-up period |
| :-------- | :------- |
| `100` | `1` |
| `100` | `15` |
| `100` | `25` |
| `100` | `50` |
| `100` | `100` |
| `500` | `100` |
| `1000` | `1` |
| `2000` | `1` |
| `3000` | `1` |

- При нагрузке до 500 пользователей: система работает стабильно, ошибки отсутствуют, среднее время отклика 2-5 мс, 100% пропускная способность.
- При нагрузке 1000 пользователей: резко возрастает среднее время отклика 400-700мс, сервер обрабатывает в среднем 550 запросов в секунду, ошибки отсутствуют.
- При нагрузке 2000 пользователей: среднее время отклика составляет 900мс, сервер обрабатывает в среднем 590 запросов в секунду - пропускная способность практически не снижается, ошибки отсутствуют.
- При нагрузке 3000 пользователей: среднее время отклика составляет 1000мс, сервер обрабатывает в среднем 850 запросов в секунду, но при этом появляются массовые ошибки - около 65% запросов не проходят. Это указывает на деградацию производительности и перегрузку сервера.

По результатам тестов можно сделать следующие выводы:
- При низкой и средней нагрузке (до 500 пользователей) приложение работает стабильно, ошибки отсутствуют.
- При нагрузке 1000-2000 пользователей ошибок нет, но увеличивается время отклика, пропускная способность составляет около 570 запросов в секунду.
- Начиная с 3000 пользователей появляются массовые ошибки около 65%, приложение не справляется с нагрузкой.

Такие результаты работы POST-запроса при нагрузочном тестировании могут быть связаны как с неэффективной обработкой запросов внутри приложения, так и с ограниченными ресурсами локальной машины, на которой проводилось тестирование.

## Запуск проета

Клонировать репозиторий

```bash
  git clone https://github.com/TatianaNai/restful-api.git
```

Переключиться на ветку

```bash
  git checkout JIRA-24091
```

Запустить тесты

```bash
  mvn clean test -Dlogin=… -Dpassword=… -Dport=…
```

Запустить тесты + Performance тесты

```bash
  mvn clean verify -Dlogin=… -Dpassword=… -Dport=…
```
